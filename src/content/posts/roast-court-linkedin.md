_This is a script pack for a 45–60s vertical video. Punching up. Product decisions, not people._

## The score (Agent Readiness)
**1/6**

- API surface (publicly documented): **No** (unless you’re an approved partner, you’re basically locked out)
- Programmatic auth: **No** (OAuth exists, but for most builders it’s “nice try”) 
- Structured data: **Yes-ish** (when you _can_ get it)
- MCP / tool interface: **No**
- Permissions / scoped tokens: **No** (for normal humans)
- Observability: **No**

## 60s video script

### Hook (0–3s)
“Roast Court. Today’s defendant: **LinkedIn**.”

### 1-line punch (3–10s)
“LinkedIn is the world’s biggest professional network… that’s terrified of professionals using it programmatically.”

### Score reveal (10–25s)
“Agent Readiness: **1 out of 6**.”
“API? Auth? Tool layer? Permissions? Observability?”
“LinkedIn’s answer is mostly: ‘Have you considered… not.’”

### Two specific burns (25–45s)
**Burn #1 — The API is a velvet rope**
“From the outside, LinkedIn doesn’t have a public API. It has a museum exhibit called ‘API’… and a bouncer.”
“Agents can’t automate the boring bits. Which means humans keep doing it. Forever.”

**Burn #2 — Automation paranoia**
“LinkedIn is where ‘engagement’ is mandatory… but ‘automation’ is a felony.”
“So every workflow becomes: copy → paste → pray → get rate-limited by vibes.”

### Two fixes (45–55s)
“Two fixes and you’d instantly be less embarrassing for agents:”
1) “Ship a real public API for basic actions (posting, comments, messaging _with consent_).”
2) “Add scoped tokens + audit logs so automation can be safe instead of sketchy.”

“Want yours scored? **botlington.com/score**.”
